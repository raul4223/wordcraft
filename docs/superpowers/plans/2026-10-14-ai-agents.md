# AI Agents (MCP connect) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One-click connection of Claude (app + Code), Codex and Antigravity to the open WordCraft
document over MCP, gated by an "Allow AI agents" switch, with agent edits as tracked changes.

**Architecture:** new `crates/agents` (client configs), `--agent` on `wordcraft-cli mcp`, a second
control server (port 7979) started through a `Services` hook, agent-aware request draining in
`ui-egui`, and an "AI agents" dialog/button.

**Tech Stack:** Rust, serde_json, egui, egui_kittest.

**Spec:** `docs/superpowers/specs/2026-10-14-ai-agents-design.md`

## Global Constraints

- Port `AGENTS_PORT = 7979`; server entry `<cli> mcp --connect 127.0.0.1:7979 --agent <Name>`; entry name `wordcraft`.
- Backups at `<file>.wordcraft-backup`; temp-file + rename writes; unparsable JSON is never overwritten.
- No panics/unsafe; nothing below L6 depends on egui; `cargo xtask wasm` stays green (agents crate must build for wasm32).
- New UI strings in every i18n catalog (tests require all keys in all catalogs).
- Commits `AI.n: …`; dev builds in `$TMPDIR/wordcraft-dev`, deleted at the end.

## Review Focus

- `~/.claude.json` is large and owned by Claude Code: connect must keep every other key. (Task 1 `json_set_keeps_other_keys`.)
- Codex config with `[mcp_servers.wordcraft.env]` subtable: disconnect removes it too, keeps neighbours. (Task 1 `toml_remove_drops_subtables`.)
- Agent request while the switch is off: refused, nothing changes. (Task 3 `agent_request_refused_when_off`.)
- Agent edit when the user already had tracking on and a custom author: both restored. (Task 3 `agent_edit_restores_user_settings`.)
- Path with spaces/quotes in the CLI path (`/Applications/WordCraft.app/...`): escaped in TOML/JSON. (Task 1 `toml_escapes_strings`.)
